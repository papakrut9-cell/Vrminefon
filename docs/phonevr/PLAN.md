# Phone VR: план и точки интеграции

Наша цель — VR Horizon на обычном Android-телефоне: экран в Cardboard-очках показывает
SBS-стерео, голова управляется гироскопом телефона, Joy-Con работают как VR-контроллеры.

База — HorizonCraft-VR (уже форк Android-порта Horizon). В нём VR сделан через OpenXR
под Quest; телефонная сборка без OpenXR стартует плоской. Мы заменяем источник позы и
цель рендера, не трогая игровую логику.

## Что где (карта кода)

|Узел|Где сейчас|Что делаем|
|---|---|---|

|Блит глаза в цель|`crates/horizon-xr/src/blit.rs`|Блит в экранную SBS-поверхность (левый глаз — левая половина, правый — правая).|
|Рендер с двумя глазами (`Globals::stereo_*`)|`crates/horizon-client-render/src/gfx.rs`|Переиспользуем: per-eye путь уже есть.|
|Single-pass stereo (multiview)|`crates/horizon-client-render/src/gfx/stereo.rs`|Не трогаем (опция `HORIZON_XR_STEREO`).|
|Контроллеры → геймпад|`crates/horizon-xr/src/pad.rs`|Источник: Joy-Con от Android (события gamepad'ов NativeActivity).|

## Фазы

### Фаза 0 — база (текущая)
- Манифест без OpenXR; собственный CI (`.github/workflows/android-apk.yml`) собирает
  запускаемый APK. Проверяем на телефоне: игра стартует плоской, файлы качаются в приложении.

### Фаза A — SBS + голова
- Готово: `crates/horizon-phonevr` — Android-сенсоры через NDK `ASensor*` без JNI,
  поток событий на ALooper, `recenter()`, при `HORIZON_PHONEVR=1` стартует из
  `android_main` и раз в секунду пишет позу и активный источник в лог (проверка по adb).
- Готово (по bugreport с Infinix X6850/MediaTek): каскад источников. Подписываемся сразу
  на четыре сенсора (game rotation vector 15, rotation vector 11, акселерометр 1,
  гироскоп 4) и выбираем самый свежий живой: 15 → 11 → собственная склейка из сырой пары.
  Прошивочный game_rotvec на MTK умирает молча (подписка жива, события стоят, accuracy 0) —
  читер фриз ловит по накопленному повороту гироскопа (≥ 0.1 рад за ≥ 0.75 с без движения
  кватерниона относительно опорного — ловит и медленные повороты головы, не только быстрые),
  по свежести и по accuracy == 0 дольше секунды у rotation vector, и передаёт управление
  дальше без прыжка головы (origin пересчитывается). На телефонах без
  fused-стеков работает собственный комплементарный фильтр: гироскоп ведёт поворот,
  акселерометр кладёт горизонт и учит bias гироскопа в покое. Числа порогов — в начале
  `crates/horizon-phonevr/src/lib.rs`; тесты на хосте (11) покрывают каскад, хендоверы и фильтр.
- Готово: рендер (`gfx.rs`: `render_phone`): вместо OpenXR-свапчейна каждый глаз рисуется
  в оффскрин-таргет (полширины окна) с камерой от `frame.yaw/pitch`, половины копируются
  в свапчейн окна бок о бок; голова в камеру — `horizon_phonevr::view_rotation()` через
  `xr_look` (только в игре, меню не вертится с телефоном). Включатель: `HORIZON_PHONEVR=1`
  или строка `phonevr=1` в `horizon-vr.txt`.
- Готово (починка после железного теста): запрашивался сенсор с id 16 — это
  `ASENSOR_TYPE_GYROSCOPE_UNCALIBRATED`, его показания (рад/с) летели в камеру вместо
  кватерниона, отсюда «конвульсии» картинки на телефоне. Правильно по NDK:
  game rotation vector = **15**, rotation vector = **11** (закреплено canary-тестом).
  Отдельный «фолдинг» ландшафта (`HORIZON_PHONEVR_TURN`) удалён: и свежее чтение, и
  recenter проходят через один базовый поворот ENU→камера (`WORLD_TO_VIEW`), так что
  постоянный поворот телефона в очках сокращается алгебраически. Направление взгляда
  извлекается как дельта (`atan2`) от текущего yaw игры — самая короткая дуга, без
  рывков через ±180°. Математика крейта проверяется тестами на хосте
  (`cargo test -p horizon-phonevr`).
- Переключение: `HORIZON_PHONEVR=1`; иначе игра ведёт себя как плоская.
- Готово (как в Vivecraft/Boardcraft-VR): тумблер «Телефон VR» в настройках лаунчера
  (`ProfileActivity`, карточка VR settings) — пишет `phonevr=` в `horizon-vr.txt`; голова
  центрируется заново при входе в игру (`recenter()` по фронту `playing` в `xr_look`).

### Фаза B — Joy-Con как контроллеры
- Joy-Con парсятся Android'ом как отдельные HID-геймпады (Android 11+).
- События NativeActivity мапим в существующий геймпад-слой игры (по образцу `pad.rs`):
  стик — движение/камера, кнопки — удары/блоки/прыжок.

### Фаза C — руки 3DoF
- Гироскоп каждого Joy-Con → ориентация руки в мире (как «виртуальные трекеры» Driver4VR:
  поза фиксируется у плеча, ориентация вращает модель).
- Источник IMU: сначала сенсоры Android HID; если телефон не отдаёт IMU геймпада —
  служба чтения BLE HID в Java-части (позже).

### Фаза D — полировка
- Коррекция дисторсии линз (модель Brown, параметры Cardboard из QR-кода).
- HUD и меню как панели в мире (`Panel::Head`/`Panel::Room` из `horizon-xr`).
- Цель 72 Гц на средних телефонах, рескейл рендера (`RESOLUTION_SCALE`).

- Перенос на Java SensorManager (как у Cardboard/PhoneVR/RiftCat/ALVR): raw NDK-очередь
  `ASensor*` на прошивке MediaTek (Infinix X6850) молча переставала доставать события,
  тогда как контракт Java-фреймворка HAL обязан соблюдать. `PhoneVrSensors.java`
  регистрирует те же четыре сенсора и отдаёт чтения в JNI-колбэк; каскад и математика
  не изменились. Класс ищется через classloader активности (FindClass на прицепленном
  потоке классы приложения не видит).

## Честные ограничения
- Трекинг 3DoF: рукам хватит гироскопов Joy-Con, позиционного трекинга нет.
- Vulkan обязателен (GLES-фолбэк для VR непригоден — нужны двухслойные цели).
- Horizon юридически неофициален; нужна купленная Java Edition.
